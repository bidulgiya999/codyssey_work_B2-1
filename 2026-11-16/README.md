프로그램 소스는 저장소 루트의 [budget_app](../budget_app)에 있습니다. 아래 명령은 `budget_app`이 있는 프로젝트 루트에서 실행합니다. 이 문서가 있는 `2026-11-16` 폴더 안에서 실행하는 것이 아닙니다. 전체 기능과 저장 구조는 [기존 README](../README.md)를 참고하세요.

## 1. VS Code 실행 준비

이 컴퓨터의 작업 폴더는 `C:\Users\1234v\Desktop\calculator`입니다. VS Code의 **파일 → 폴더 열기**로 해당 폴더를 열고 **터미널 → 새 터미널 → PowerShell**을 선택합니다.

```powershell
cd "C:\Users\1234v\Desktop\calculator"
$ledgerPython = 'C:\Users\1234v\AppData\Roaming\uv\python\cpython-3.15-windows-x86_64-none\python.exe'
& $ledgerPython -m budget_app --help
```

- `$ledgerPython`은 이 컴퓨터에 설치된 Python의 실행 경로입니다. 새 터미널을 열면 다시 설정합니다.
- 다른 컴퓨터는 설치된 Python 경로로 바꾸거나 `python -m budget_app ...`로 실행합니다.
- `PS C:\...>`는 터미널이 자동 표시하는 현재 위치입니다. 직접 입력하지 않습니다.
- 폴더로 이동할 때는 경로만 입력하지 않고 `cd "경로"`를 사용합니다.
- 명령 끝에 `\`를 붙이지 않습니다. 명령을 한 줄씩 실행합니다.
- 명령은 `PS C:\...>`에서 입력하고, `날짜:` 등 질문이 나오면 답만 입력합니다.

**확인 결과:** 도움말에 `add`, `list`, `search`, `summary`, `budget`, `category`, `update` 등의 명령이 표시되었습니다.

**설명 멘트:**
> Python 표준 라이브러리로 만든 콘솔 가계부입니다. 도움말로 명령을 확인할 수 있고, 데이터는 기본 data 폴더에 저장됩니다.

PowerShell의 명령 입력 줄에 `2026-11-16`만 입력하면 뺄셈으로 계산되어 `1999`가 나옵니다. 날짜는 반드시 프로그램이 `날짜(YYYY-MM-DD):`를 물어볼 때 입력합니다.

## 7. 거래 수정

### 거래 id 확인과 변수 설정

```powershell
& $ledgerPython -m budget_app list --limit 5
$expenseId = 'TX-699cbe9e3570482c8f9c48ab35060b9c'
```

위 id는 이번 실습에서 생성된 food 지출의 실제 id입니다. 새로 거래를 등록하거나 다른 데이터를 사용한다면 목록에서 해당 지출의 id를 확인해 바꿉니다. 월급 거래 id와 혼동하지 않습니다.

### 수정 및 확인

```powershell
& $ledgerPython -m budget_app update --id $expenseId --amount 12000 --memo 저녁
& $ledgerPython -m budget_app list --limit 5
```

**확인 결과:** 지출 금액이 15,000원에서 12,000원으로, 메모가 점심에서 저녁으로 변경되었습니다. 날짜, 타입, 카테고리와 태그는 유지되었습니다.

**설명 멘트:**
> 수정은 옵션 방식입니다. 거래 id를 기준으로 지정한 필드만 바꾸고, 지정하지 않은 정보는 유지합니다.

### 없는 id 오류 확인

처음에는 안내용 문구 `여기에_지출_id_붙여넣기`를 그대로 변수에 넣어 없는 데이터 오류가 발생했습니다. 실제 거래 id로 변수를 다시 설정한 후 수정에 성공했습니다. 안내용 문구는 실제 id가 아닙니다.

## 8. 잘못된 입력과 종료 코드 확인

### 명령

```powershell
& $ledgerPython -m budget_app update --id $expenseId --amount 0
$LASTEXITCODE
& $ledgerPython -m budget_app list --limit 5
```

### 확인 결과

- 금액 0을 거부하고 양수 정수 입력 안내와 힌트를 표시했습니다.
- 오류 직후 `$LASTEXITCODE`를 실행했을 때 `1`이 출력되었습니다.
- 목록에서 기존 금액 12,000원과 메모 저녁이 유지되는 것을 확인했습니다.

`$LASTEXITCODE`는 Python 명령이 종료한 직후 확인합니다. 이후 다른 Python 명령을 실행하면 해당 명령의 종료 코드로 바뀝니다.

**설명 멘트:**
> 금액 0은 유효하지 않으므로 오류 종료합니다. 스택트레이스 대신 원인과 해결 힌트를 출력하고, 실패한 수정은 기존 거래를 변경하지 않습니다.

```powershell
& $ledgerPython -m budget_app list --limit 10
```

위 id는 이번 실습의 실제 지출 id입니다. 새 데이터로 실습하는 경우 목록에서 삭제할 거래의 id를 확인해 바꿉니다.

### 확인 결과

사용자가 거래 삭제 완료를 확인했습니다. 삭제는 id가 일치하는 거래를 대상으로 합니다. 다른 거래는 유지하며, 임시 파일에 나머지 거래를 기록한 후 원자적으로 교체하는 방식입니다.

### 같은 id로 재삭제 및 종료 코드 확인

```powershell
& $ledgerPython -m budget_app delete --id $expenseId
$LASTEXITCODE
```

사용자가 같은 id로 다시 삭제했을 때 없는 데이터 오류와 해결 힌트가 출력되고, 직후 확인한 종료 코드가 `1`임을 확인했습니다. 이미 삭제된 거래이므로 두 번째 요청을 거부하는 것이 정상입니다.

**설명 멘트:**
> 거래 id로 특정 거래를 삭제합니다. 이미 삭제된 id를 다시 요청하면 없는 데이터로 안내하고 오류 종료합니다. 삭제는 임시 파일에 기록한 뒤 원자적으로 교체하는 방식입니다.

## 현재 시점의 정리

- 실행 확인 범위: 도움말 → 수입 추가 → 목록 → 검색 → 지출 추가 → 예산/요약 → 수정 → 잘못된 입력과 종료 코드 → 카테고리 관리와 삭제 보호 → CSV 내보내기 → CSV 가져오기 → 거래 삭제와 재삭제 오류 처리.
- 2026년 11월의 12,000원 지출을 삭제했습니다. 추가 입력이 없다면 해당 월은 수입 3,000,000원, 지출 0원, 잔액 3,000,000원이며 예산 사용률은 0%입니다. 이는 현재 거래에 따른 예상 요약으로, 삭제 후 summary를 별도로 실행한 결과는 아닙니다. CSV 예제는 2024년 1월 거래이므로 2026년 11월 요약에 합산되지 않습니다. 추가 입력이 없다면 전체 거래는 월급 1건과 가져온 3건으로 총 4건입니다.
- 저장 파일은 프로젝트 루트의 `data/transactions.jsonl`, `data/categories.jsonl`, `data/budgets.jsonl`입니다.
- 이 날짜 폴더는 실행 방법과 실습 결과를 기록합니다. 프로그램 소스와 실제 실행 데이터는 별도이며, 이 문서를 실행하거나 업로드하는 것만으로 거래가 추가되지는 않습니다.
- 백업은 기존 코드에 구현되어 있으며 다음 실습에서 실행 결과를 확인할 예정입니다.
