# CRUD 쉽게 이해하기

CRUD는 데이터를 다루는 네 가지 기본 동작입니다. **C=Create(만들기), R=Read(읽기), U=Update(고치기), D=Delete(지우기)**이며 보통 '크루드'라고 읽습니다. Python의 특정 문법이나 라이브러리 이름은 아닙니다. 파일 기반 프로그램과 데이터베이스 모두에 쓰는 개념입니다.

## 가계부 한 건으로 생각하기

| 단계 | 일상적인 뜻 | 가계부 예 | 명령 |
| --- | --- | --- | --- |
| C: 생성 | 새 기록 만들기 | 점심 15,000원을 새 거래로 저장 | add |
| R: 조회 | 있는 기록 읽기 | 점심 거래를 목록이나 검색으로 확인 | list, search |
| U: 수정 | 기존 기록의 일부 바꾸기 | 같은 거래의 금액을 12,000원으로 고침 | update |
| D: 삭제 | 기존 기록 없애기 | 그 거래를 id로 찾아 제거 | delete |

수정은 원래 id를 유지하며 일부 값만 바꿉니다. 새 거래를 추가하는 것과 다릅니다. 조회는 화면에 보여줄 뿐 저장된 거래를 바꾸지 않습니다. 삭제는 지정한 id 한 건을 제외하고 다른 거래는 보존합니다.

## 왜 id가 필요한가요?

같은 날짜에 점심을 두 번 기록할 수도 있고 금액이나 메모도 같을 수 있습니다. 날짜나 금액만으로는 어느 거래를 고칠지 모호하므로 고유 id로 대상을 구분합니다. 실제 프로그램은 UUID 기반 TX-... id를 만들고, update/delete에서 그 id를 사용합니다.

## 코드에서는 어디인가요?

| 동작 | 서비스 | 실제 저장/조회 |
| --- | --- | --- |
| C | BudgetService.add | TransactionRepository.replace(replacement=transaction) |
| R | BudgetService.search | iter_all → read_jsonl → yield |
| U | BudgetService.update | find → 새 객체 생성 → 옛 거래 제외·수정본 삽입 |
| D | BudgetService.delete | find → 해당 id만 제외하고 재작성 |

여기서 저장소의 replace는 C/U/D가 공통 사용하는 파일 병합·교체 기능입니다. 수정만 뜻하는 함수 이름은 아닙니다. 같은 저장 로직에 어떤 인자를 주느냐에 따라 추가·수정·삭제를 구분합니다.

## 다른 명령은 CRUD 중 무엇인가요?

- summary: 저장 거래를 읽어 합산하는 Read입니다.
- export: 거래 관점에서는 Read이며, 읽은 결과를 별도의 CSV 파일로 씁니다.
- import: 각 CSV 행을 새 거래로 추가하는 일괄 Create입니다. 같은 파일을 다시 가져오면 새 id를 가진 중복 거래가 생길 수 있습니다.
- category add/list/remove: 카테고리 데이터의 Create/Read/Delete입니다.
- budget set: 해당 월이 처음이면 Create, 이미 있으면 Update입니다.
- backup: 기존 자료를 읽어 복사본을 만들며 원본 거래를 수정·삭제하지 않습니다.

## 안전한 CRUD란?

C/U는 날짜·양수 금액·등록된 카테고리를 검증합니다. U/D는 대상 id의 존재를 먼저 확인합니다. 실패하면 기존 거래가 바뀌지 않아야 합니다. 파일 쓰기는 임시 파일을 완성한 뒤 원자적으로 교체하며, 동시 명령의 덮어쓰기는 별도 잠금으로 방지합니다.

실제 실습에서는 15,000원을 12,000원으로 수정했고, 0원 수정은 거부되어 기존 값이 남았습니다. 삭제는 성공했으며 같은 id를 다시 삭제하면 없는 데이터 오류가 나왔습니다. 이 과정이 CRUD와 입력 검증·데이터 보호를 함께 보여줍니다.

## 평가 설명 멘트

> CRUD는 데이터의 생성, 조회, 수정, 삭제를 뜻합니다. 제 가계부에서는 add가 생성, list와 search가 조회, update가 수정, delete가 삭제입니다. 수정과 삭제는 고유 id로 대상을 구분하고, 검증과 안전한 파일 교체로 기존 데이터를 보호합니다.
